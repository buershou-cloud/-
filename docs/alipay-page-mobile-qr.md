# 支付宝电脑网站支付：手机打开官方付款码

本次更新只调整手机收银台的 `ALIPAY_PAGE`：顾客扫码打开本站收银台、输入金额后，由服务器获取该笔支付宝电脑网站支付订单的官方付款码链接。支付宝内直接打开这个链接，其他手机浏览器使用支付宝扫码入口打开它。

调用的支付产品仍为 `ALIPAY_PAGE`，接口仍为 `alipay.trade.page.pay`，产品码仍为 `FAST_INSTANT_TRADE_PAY`。手机取码请求在签名前设置 `qr_pay_mode=4`、`integration_type=PCWEB`。原订单号、金额、选定通道、应用授权、通知地址及分账参数保留。电脑端继续提交原来的付款表单；其他支付产品继续原来的流程。

参考了公开易支付项目的手机 PC 支付分支，只参考流程，没有复制其源码或关闭 HTTPS 证书校验：

- [同产品手机取码流程](https://github.com/maajiko/Epay/blob/a4d0f0421cfcbc573913c8007bde3d0c04a5713a/plugins/alipay/alipay_plugin.php#L176)
- [参考项目的 PAGE 请求](https://github.com/maajiko/Epay/blob/a4d0f0421cfcbc573913c8007bde3d0c04a5713a/includes/vendor/cccyun/alipay-sdk/src/AlipayTradeService.php#L90)

取码仅访问受限的支付宝官方 HTTPS 网关和收银台，限制跳转、耗时与响应大小，每单独立会话。只读取指定隐藏付款码字段，不执行远端脚本、不访问最终付款码。隐藏字段属于官方页面实现细节，支付宝以后改变页面时可能需要适配。

取码未确认时保留原订单，显示简短提示，不回退到电脑付款页，也不自动重新下单。当前手机页面提前保存原订单身份；再次点击或刷新可继续已取得的原付款码，未确认时联系商家查询原单。显式“新一笔付款”只清空表单，仍需要重新填写金额并点击确认；未确认订单在本次入口等待期限内禁止新笔。入口等待期限是客户端上限，不保证支付宝二维码的实际有效期，也不代表订单已付款或已关闭。

## 更新方式

1. 在宝塔停止当前 Java 项目。
2. 将本更新的 `payment-gateway-0.1.0-SNAPSHOT.jar` 上传覆盖：`/www/wwwroot/www.bjfits.com/--main/target/payment-gateway-0.1.0-SNAPSHOT.jar`。
3. 保持原 Java 21、数据库、数据目录和启动配置，重启项目。
4. 确认 `http://127.0.0.1:18081/actuator/health` 返回 `UP`。浏览器刷新收银台页面。

只需要替换这个 JAR，无需上传其他文件或清空数据目录。

## 验证范围

本地后端 386 项检查、页面 158 项检查通过，包含本次取码和重复点击处理、电脑端及其他产品回归。没有使用真实通道发起付款。部署后，需要用手机扫描原收银台入口并填写金额，确认进入支付宝本单付款页面；电脑打开同一收银台仍应保持电脑支付流程。支付宝最终使用密码、指纹或其他确认方式由支付宝决定。
