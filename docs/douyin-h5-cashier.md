# 抖音 H5 收银台的电脑与手机流程

原电脑收银台会先创建抖音 H5 订单，再将上游 `h5_url`（本系统的 `redirectUrl`）直接生成二维码。这使下单设备与打开收银台的设备分离。用户反馈：手机扫描收银台入口后下单正常，而电脑填写金额后再扫描支付链接二维码提示“鉴权失败”。本次修改针对这个可确认的流程差异；不把该通用报错一概解释为 IP、证书或域名问题。

## 更新后的操作

1. 在电脑的抖音 H5 收银台输入金额和订单标题。
2. 页面显示“手机确认付款”入口二维码。此时尚未创建支付订单，也不会轮询或关闭支付订单。
3. 手机扫码打开同一收银台，金额、标题和通道／商户会预填。
4. 在手机核对收款方与金额，点击确认后，才由手机当前访问环境发起 H5 下单，并跳转到抖音官方收银台。

入口参数仅用于公共收银台表单预填，可以在手机修改；它不是已锁定金额的业务订单，也不代表已经支付。入口二维码中不包含密钥、授权码、旧支付链接或支付订单号。电脑页面不会显示手机端订单的实时支付状态；以订单管理、可信通知或订单查询核实结果。

收银台隐藏“本订单需要分账”选择及说明，抖音订单仍默认开启分账，入口保留内部设置的传递。后台分账操作不受影响。

支付宝及抖音 Native 扫码继续使用原流程。本次不改支付签名、分账处理、商户 API 参数校验或通道域名配置，也没有新增数据库表。

## 自己开发的网站如何接入

- 手机 H5：选择 `DOUYIN_H5`，商户服务器传付款人的实际 `extra.payer_client_ip`，把返回的 `data.redirectUrl` 原样交给付款人当前浏览器跳转。不要用网站服务器的 IP 代替付款人。
- 跨设备扫码：可以选已开通的 `DOUYIN_NATIVE`，把 `data.qrCode` 生成二维码；如保留 H5，二维码应指向自己网站的订单确认页，在付款人手机打开并确认后，才使用该手机访问上下文调用商户 API。
- 外部商户的订单号、金额及签名由其服务器从自己的业务订单读取，不能用公共收银台预填地址替代商户订单关联。付款状态仍需验签并核对金额后更新。

本系统收银台更新不会自动修改对接方网站的二维码代码；对接方若也把 H5 的 `data.redirectUrl` 直接制成跨设备付款码，需要同步调整。

## 官方资料

- [H5 返回的 h5_url 及用户终端 IP 字段](https://pkg.go.dev/github.com/douyinpay/douyinpay-go/services/pay/h5)：H5 返回用于拉起收银台的中间页，场景信息记录付款人客户端 IP。
- [Native 返回的 code_url](https://pkg.go.dev/github.com/douyinpay/douyinpay-go/services/pay/native)：用于生成供用户扫码的支付二维码。
- [官方接入注意事项](https://github.com/douyinpay/douyinpay-skills/blob/main/douyinpay-payment-integration/references/coding-guide.md)：H5 支付需在抖音支付商家平台配置 H5 支付域名。若手机直接下单仍失败，需要继续核对域名配置、实际请求和平台返回信息。
