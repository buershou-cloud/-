# Telegram 群收款提醒

本次增加后台“账户管理 → 收款提醒”。沿用现有机器人，只在支付平台确认真实收款成功后发送提醒到指定群。支付宝、抖音以及网站 API、通道收银台、商户收银台的收款共用这条通知流程。

## 配置

1. 将现有机器人加入接收提醒的 Telegram 群，并允许它发送消息。
2. 使用超级管理员登录本系统，打开“账户管理 → 收款提醒”。
3. 填写 BotFather 提供的机器人密钥和接收群 ID。群 ID 通常是负数，填写完整值，不能填写邀请链接或普通群名称。
4. 保存后点击“发送测试提醒”。该按钮会向已保存的接收群发送一条测试消息；保存设置本身不会发消息。
5. 确认群内收到测试消息后，开启“收款成功后提醒”并保存。

密钥只填写在后台，读取设置不会回显密钥，输入框留空保存可沿用已设置的密钥。配置只允许超级管理员查看和修改。

本功能使用 Telegram 官方 [sendMessage](https://core.telegram.org/bots/api#sendmessage) 接口。它不会更改现有机器人的 webhook，也不会读取群聊内容。群 ID 可从原机器人的配置或已接收的更新中获取；需要检查更新时，可参考官方 [getUpdates](https://core.telegram.org/bots/api#getupdates)。现有机器人配置了 webhook 时应使用它已有的更新记录，不必删除 webhook。

## 提醒范围

提醒包含收款金额、商户、通道、订单号、平台单号和本次确认时间，并附带今日已确认收款笔数、收款总金额；本单计入合计。不包含付款人的账号、密钥、签名或完整支付报文。

每日统计按真实支付成功事件记账，与 Telegram 是否发送成功无关；重复回调、消息重试和重启都不重复计数。统计按通知配置的时区切日，默认 `Asia/Bangkok`，可通过 `payment.telegram.time-zone` 设置业务时区。机器人关闭期间，本版本仍会记录真实成功事件供当日统计，但不会把关闭期间的收款在重新开启后逐条补发。

本统计从部署此版本后开始记录。旧版本缺少独立、可信的成功事件账本，升级不会把旧历史或人工完成单自动加入统计；部署当天的新统计仅包含本版本确认的收款。次日起可覆盖整日的成功事件。

创建未支付订单、付款页面跳转、人工标记完成、补单、退款、分账、代付、预授权冻结和解冻不会发送收款提醒。预授权实际扣款得到明确成功结果后才可提醒。通知和查单使用原始支付状态判断，抖音退款状态不能当作新收款。

重复回调和重复查单不会重复创建提醒。应用启动仅处理已有待发记录，不扫描历史完成订单。未启用时不创建提醒；关闭后待发提醒暂停。

消息先保存在服务器，再由后台独立发送。发送失败会按间隔重试，Telegram 限流时按其要求等待。不会让 Telegram 网络请求阻塞支付回调，也不会因为提醒失败重新下单、付款或改变订单状态。

若服务器存储故障导致首次成功事件完全无法写入，后台会显示通知目录错误；这种事件没有可恢复的记录，修复目录后需要按支付平台账单核对。已写入的统计和待发记录可以恢复；一笔提醒写入失败不会挡住其他独立收款的统计。

Telegram 文本发送接口没有本系统可使用的幂等参数。在极少数“消息已送达但应答丢失”或发送后进程意外退出的情况下，重试可能产生重复提醒；请使用订单号识别同一笔收款，群消息不能代替支付平台账单对账。

## 部署

停止当前宝塔 Java 项目，上传覆盖 `/www/wwwroot/www.bjfits.com/--main/target/payment-gateway-0.1.0-SNAPSHOT.jar`，再按原 Java 21、工作目录、数据库和启动参数启动。只需替换 JAR，不清空数据目录。

机器人设置、每日统计、扣款确认标记和提醒记录默认位于项目运行目录下的 `data/telegram-notifications/`。保留该目录，才能在应用重启后保持设置、统计和去重记录。不要把这个目录上传到源码仓库或放到对外提供静态文件的目录。

上线后先使用“发送测试提醒”核对群和服务器网络，然后用一笔真实支付成功的收款核对自动提醒。本地开发验证不会向真实 Telegram 群发送消息。
