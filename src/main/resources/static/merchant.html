你的接入信息

所有接口由你的网站服务器发起 POST JSON 请求。MD5 与 RSA2 使用同一组接口，选择已开启的签名方式即可。密钥在“密钥管理”中单独配置。

从检查接入到确认到账

1 · 在服务器验证接入

安装 Node.js 20.6 或更新版本，将两个示例文件放入同一目录。配置环境变量，运行 check；此操作不创建订单、不扣款。

2 · 用自己的网站订单支付

选择当前商户可用的支付产品，填写唯一订单号、金额和你的网站通知地址，运行 pay。

3 · 验签后更新订单

处理平台通知，核对商户、订单和金额，并幂等更新业务订单。用 query 查询最终状态。

产品列表以当前商户绑定且启用的支付通道为准。

            INTEGRATION GUIDE
            
服务端接入说明

            
以下字段与商户 JSON API 一致。可下载运行示例来完成签名、发送请求与验签响应；不要把商户私钥放入网页脚本。

          

          

            
先检查签名与通道配置

            
POST 。只校验接入信息，不创建订单、不扣款。

            

            
返回的 data 包含 merchantId、serverTime、signMode、channelIds 和 readiness。查看 readiness.availableChannelCount、availableChannelIds、products 确认商户可用配置；数量为 0 时，请联系平台配置通道。

            
readiness.configurationWarnings 列出需要平台处理的通道配置问题；出现 GATEWAY_CALLBACK_NOT_CONFIGURED 时，请让平台管理员配置网关支付回调地址后重新检查。

          

          

            
创建支付订单

            
POST 。下方是完整签名请求的结构预览；SDK 的 pay.json 只需业务字段，签名字段由 SDK 自动生成。

            
字段要求

              
product必填。选择“网站接入”页列出的当前可用产品。

              
outTradeNo / subject必填。自己网站的唯一订单号与订单标题。

              
totalAmount必填。单位元，至少 0.01。SDK 使用两位小数的字符串，例如 "1.00"。

              
notifyUrl填写你自己网站可接收通知的服务器地址，如 https://merchant.example/payments/notify。

              
returnUrl客户付款后的页面返回地址。页面跳转本身不能作为支付成功依据。

              
merchantId / signType / timestamp / nonce / sign每次请求必填。由 SDK 生成，signType 必须在商户已开启的范围内。

            

            

            

            
pay.json：可供运行示例读取的业务参数

读取并验证平台响应

            
先检查 HTTP 状态并验签，再读取 data。外层 code=SUCCESS 仅表示请求处理成功；支付是否成功必须查看 data.status。

            

            
路径含义

              
code / message商户接口处理结果。错误响应可能只有这两个字段及校验详情，并不包含签名。

              
data.status当前操作的网关状态。普通支付经核对为 SUCCESS 才可作为收款依据；退款 SUCCESS 表示退款成功，预授权冻结成功也不代表收款。CREATED / PAYING / PENDING / UNKNOWN 需要继续核对；FAILED / CLOSED 不能当作已付款。

              
data.outTradeNo / data.tradeNo商户订单号与支付平台交易号。

              
data.qrCode / data.redirectUrl / data.redirectHtml按产品返回二维码内容、跳转链接或支付表单。APP 产品也可能使用 data.raw.order_string。

              
timestamp / signType / sign平台响应签名。SDK 会请求可跨语言验签的响应格式并自动校验。

            

          

          

            
接收平台支付通知

            
平台向你提供的 notifyUrl 发起 POST，Content-Type 为 application/x-www-form-urlencoded; charset=UTF-8。下面展示表单解码后的 camelCase 字段；此通知由本平台重新签名。

            

            
    
              
  1. 先按表单解码，使用 signType 指定的方式验证除 sign 外的完整参数。
    2. 
              
  2. MD5 使用商户密钥验签；RSA2 使用平台公钥验签。通知签名方式可能与原请求不同，以通知的 signType 为准。
    3. 
              
  3. 核对 merchantId、outTradeNo、tradeNo、totalAmount 与本地订单。仅 status=COMPLETED 可作为普通支付完成依据；tradeStatus 保留上游支付状态，其他状态不能直接发货。
    4. 
              
  4. 按订单号幂等更新业务，确认处理完成后返回 HTTP 2xx，纯文本正文 success。重复通知也应安全处理。
    5. 
            

            
notifyTime 是通知时间；通知不含请求用的 nonce。不要把商户请求的 timestamp / nonce 校验规则套到回调上。未及时收到通知时，可调用 query 核对订单。

            
未收到 HTTP 2xx 和正文 success 确认的通知会记录并重试。重试可能重复到达，请始终按商户订单号幂等处理。

          

          

            
签名与金额规则

            
每次请求都必须签名。SDK 保持现有商户请求签名规则，并为响应使用 X-Merchant-Response-Signature: canonical-v1。MD5 与 RSA2 都通过同一个 API 根地址调用。

            
    
              
  • 递归移除 sign、null 及对象中的空白字符串；对象字段按名称排序。signType、false、0、空对象和空数组仍参与签名。
    • 
              
  • 数组保留顺序并移除 null。对象和数组使用紧凑 JSON；顶层用 key=value 以 & 连接，签名前不做 URL 编码。
    • 
              
  • MD5：UTF-8 编码的签名原文后直接拼接商户 MD5 密钥，计算 MD5。RSA2：商户私钥使用 SHA256withRSA 签名并 Base64 编码。
    • 
              
  • timestamp 支持 ISO 8601 UTC、10 位秒或 13 位毫秒时间戳，允许前后 15 分钟误差。每个请求使用新的 nonce。
    • 
              
  • 金额保持两位小数字符串。扩展参数中的小数也使用字符串，避免不同语言的数字序列化改变签名。
    • 
            

            
完整规范、字段说明和跨语言规则见下载文档。请直接使用 SDK 的签名及响应校验逻辑，避免自行拼接产生差异。

          

          

            
接入失败时，按返回信息排查

            
现象检查项

              
404 / 返回 HTML使用“网站接入”中的完整地址，检查域名、部署前缀和 /merchant-api 路径；请求使用 POST JSON。

              
signature verification failed核对商户号、商户密钥和 signType；检查金额小数位、扩展 JSON 及签名前后的字段是否一致。不要使用支付宝或抖音商户的上游密钥。

              
timestamp is expired / nonce has already been used同步服务器时间；每次调用生成新 nonce 和当前 timestamp，再重新签名。业务订单号仍保持原值。

              
Sign type is not enabled检查“密钥管理”中已开启的签名方式；RSA2 请求用商户私钥，平台响应验签用平台公钥。

              
check 可用通道数量为 0 / 无匹配通道核对商户绑定通道、通道启用状态、产品及金额范围。check 不创建订单，可在调整配置后再次检查。

              
外层 SUCCESS，但客户尚未付款读取 data.status，并展示产品对应的支付链接或二维码；继续查单或等待通知。

              
未收到通知 / 重复通知检查 notifyUrl 是否是你网站的公网服务端地址，支持 POST 表单；验签、幂等处理后返回 2xx 和 success。需要确认时主动查单。
